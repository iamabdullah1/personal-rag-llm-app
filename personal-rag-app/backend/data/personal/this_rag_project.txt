# About This Project - My Personal AI Chatbot (v2.0 Agentic RAG)

## What is This Project?

This project is my personal AI chatbot - a smart conversational assistant that knows everything about me (Abdullah Akram). You can ask me questions about my skills, projects, experience, education, or anything else, and I'll give you accurate, personalized answers based on my actual information.

This is NOT a generic chatbot. This is an **Agentic RAG (Retrieval-Augmented Generation)** system that uses autonomous AI tool calling to decide how to answer your question. The AI (Groq Llama 3.3 70B) acts as an intelligent agent that autonomously decides which tools to use, executes them, reasons over the results, and generates comprehensive answers - all streamed in real-time.

## What is Agentic RAG?

Agentic RAG is an advanced AI architecture where the LLM (Large Language Model) doesn't just retrieve and generate - it **autonomously decides** what actions to take:

1. The AI receives your question
2. It decides which tools to call (personal knowledge search, web search, or GitHub stats)
3. It executes those tools and receives results
4. It reasons over the results - and may call MORE tools if needed (up to 3 rounds)
5. It generates a final answer with all the gathered context
6. If anything fails, it gracefully falls back so you always get a helpful answer

This is different from traditional RAG where every question goes through the same retrieve-then-generate pipeline. Agentic RAG is smarter and more flexible.

## MCP Server (Model Context Protocol)

This project also includes an **MCP (Model Context Protocol) server** - a protocol designed by Anthropic for exposing AI tools to external clients. I built an MCP server using FastMCP that exposes all three of the chatbot's tools:

1. **search_knowledge** - Search my personal knowledge base (ChromaDB vector search)
2. **search_web** - Search the internet (Tavily AI search with DuckDuckGo fallback)
3. **get_github_stats** - Fetch live GitHub profile and repository data

This MCP server can be used with:
- **Claude Desktop** - Anthropic's AI assistant can use my tools directly
- **Cursor IDE** - The AI coding editor can access my knowledge base and tools

Building the MCP server demonstrates my ability to work with cutting-edge AI protocols and integrate AI tools across different platforms. The MCP server shares the same tool implementations as the main chatbot, ensuring consistency.

## How This Chatbot Works (Technical Overview)

### Step 1: Data Ingestion (One-Time Setup)
- My personal information is stored in 9 text files (about me, skills, projects, education, work experience, contact, hobbies, testimonials, and this project description)
- These documents are split into smaller chunks (1000 characters with 200 overlap) using RecursiveCharacterTextSplitter
- Each chunk is converted into a 384-dimensional vector using sentence-transformers/all-MiniLM-L6-v2 (runs locally on CPU)
- These vectors are stored in ChromaDB (a local vector database with HNSW index)

### Step 2: When You Ask a Question (Agentic Pipeline)
1. Your question arrives at the FastAPI backend via POST /api/chat/stream
2. The semantic cache checks if a very similar question was asked before (0.95 cosine similarity threshold)
3. If cache HIT: the cached answer is streamed word-by-word instantly (~350ms)
4. If cache MISS: the agentic tool-calling loop begins:
   a. Your question + system prompt + conversation history (last 6 messages) are sent to Groq's Llama 3.3 70B model along with 3 tool definitions
   b. The LLM autonomously decides: should I call a tool? If yes, which one?
   c. If the LLM calls a tool (e.g., search_personal_knowledge), the tool is executed and results are sent back
   d. The LLM may call more tools or decide it has enough information (up to 3 rounds)
   e. When ready, the LLM generates the final answer, which is streamed token-by-token via SSE
5. The frontend displays tool status indicators showing which tool is being used
6. The answer is cached for future similar questions and stored in conversation memory

### Step 3: Intelligent Fallback
- If tool calling fails at any point (JSON parsing error, tool execution error), a ToolCallError is raised
- The fallback pipeline activates: manually searches ChromaDB + manually searches Tavily/DuckDuckGo
- An enriched prompt with all gathered context is sent to Groq WITHOUT tools
- The user always gets a helpful answer, even when the agentic pipeline has issues

### Step 4: Caching and Memory
- Semantic cache stores Q&A pairs with 0.95 similarity threshold, 7-day TTL, max 1000 entries, LRU eviction
- Conversation store keeps last 10 messages per session with 24-hour TTL
- Last 6 messages are sent to the LLM for contextual follow-up responses

## MCP Server Details

The MCP (Model Context Protocol) server is a separate component that exposes the chatbot's tools for use by external AI clients:

### What is MCP?
MCP is an open protocol designed by Anthropic that allows AI applications to connect to external tools and data sources. Think of it as a universal adapter for AI tools.

### My MCP Implementation
- Built using **FastMCP** library
- Shares the exact same tool functions as the main chatbot (tools.py)
- Exposes 3 tools:
  - **search_knowledge(query)**: Search my personal knowledge base using vector similarity
  - **search_web(query)**: Search the internet using Tavily (with DuckDuckGo fallback)
  - **get_github_stats(username)**: Fetch GitHub profile and repository information
- Can be connected to Claude Desktop via claude_desktop_config.json
- Can be used with Cursor IDE for AI-powered development with access to my knowledge base
